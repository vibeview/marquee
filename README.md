# Marquee

A TV catalogue for Apple TV and Android TV: three shelves of posters you
move through with the remote, a detail screen for each title, and a "My
list" you can add to. No account, no server, no network, no real video —
the eighteen titles are bundled and My list lives on the device.

**This is a deliberately small sample app.** It exists to show a complete,
working VibeView setup for an Expo + react-native-tvos project: cloud
builds for tvOS and Android TV, device verification by a coding agent
driving focus with the d-pad, signing, and store submission. Read how it
was built and shipped, with every command and its output, at
https://vibeview.io/guides/ai-agent-shipped-apple-tv-android-tv-app/ (write-up link placeholder). Copy
`vibeview.json` and the two config plugins into your own project; do not
expect much from the app itself.

Marquee was built, verified on live Apple TV and Android TV devices,
signed and submitted to TestFlight and the Google Play internal track by a
coding agent, using only the [VibeView](https://vibeview.io) CLI for
everything native. No Xcode or Android Studio was involved at any point —
Metro ran on the laptop, every native build ran in VibeView's cloud, and
every remote press of the verification flow ran on a VibeView cloud
device.

## The app

- **Home** — a "Marquee" heading and three horizontal shelves of six
  posters: Tonight, Documentaries, Kids. Below them, `My list: N titles`.
  Focus starts on the first poster of the first shelf. Left/right move
  within a shelf; up/down move between shelves and land on the shelf's
  first poster the first time, then on the poster last focused there
  (each shelf is a `TVFocusGuideView autoFocus`). Select opens Detail.
- **Detail** — the poster large on the left; title, genre and year, a
  three-sentence blurb and two buttons on the right: `Watch` (focused on
  arrival) and `Add to my list` / `In my list` (green while in the list).
  Back returns to Home with focus on the poster that was opened.
- **Now playing** — the poster blurred behind, the title, and a progress
  bar that fills over 30 seconds. Back returns to Detail.

Focus is the whole product, and it is the platform's own focus engine:
posters and buttons are plain `Pressable`s that react to the native
`onFocus`/`onBlur` events (a scale-up and a 4 px accent ring; the focused
button takes the accent fill). No JavaScript focus engine, so the device's
automation layer sees exactly the focus the user sees.

Palette: background `#0F1014`, card `#1B1D24`, ink `#F2F1EC`, secondary
ink `#9A9DA8`, accent `#E6602A`, done `#2F8F78`. Dark only.

Stack: Expo SDK 57 (managed workflow) with `react-native-tvos@0.86-stable`
and the `@react-native-tvos/config-tv` plugin (`isTV: true`, so every
build is a TV build without anyone setting `EXPO_TV`), TypeScript, React
Navigation native stack, AsyncStorage, system fonts. The generated `ios/`
and `android/` directories are not checked in — `expo prebuild` recreates
them for every build. `.npmrc` sets `legacy-peer-deps=true` because the TV
fork's prerelease version numbers do not satisfy other packages' peer
ranges under npm's strict resolution.

## Running it

```bash
npm install
npm start                 # Metro, with EXPO_TV=1
npm run typecheck         # tsc --noEmit
npx expo-doctor
```

To run it on a TV you need a debug build; this project never produced one
locally. Every image the app ships — 18 poster cards, the app icon, the
Android adaptive icon and splash mark, the seven Apple TV brand images and
the Android TV banner — is generated by `python3 scripts/make-images.py`
(Pillow). Titles and colours come from `src/data.ts`.

## `vibeview.json`

| Key | What it does |
|---|---|
| `defaultPlatform` | Platform `vibeview build` / `vibeview dev` use when `--platform` is omitted (`tvos`). |
| `metroCommand`, `metroPort` | How `vibeview dev` starts Metro when nothing is listening on the port. `npm start` already sets `EXPO_TV=1`. |
| `platforms.tvos` / `platforms.androidtv` | One entry per TV platform. `appId` is the VibeView app record, written by the CLI after the first successful cloud build — you never type it. |
| `build.command` / `build.artifact` | The debug build. tvOS: `npm ci`, `expo prebuild --platform ios`, then `xcodebuild` against the `appletvsimulator` SDK with code signing off; the artifact is the `.app` in `Debug-appletvsimulator`. Android TV: `expo prebuild --platform android`, then `gradlew assembleDebug -PreactNativeArchitectures=x86,x86_64` so the APK carries both emulator slices (the Android TV fleet mixes 32-bit x86 and x86_64). |
| `build.env` | `EXPO_TV=1` for every build, belt and braces next to the plugin's `isTV`. |
| `build.productionCommand` / `build.productionArtifact` | The signed release build for `vibeview build --cloud --production`. tvOS: `xcodebuild archive` for `generic/platform=tvOS` passing only `CODE_SIGN_IDENTITY`, then `-exportArchive` with the export options plist VibeView writes; artifact `ios/build/*.ipa`. Android TV: `gradlew bundleRelease`; artifact the `.aab`. |
| `build.autoIncrement` | VibeView keeps a per-app build-number counter and passes the next value as `VIBEVIEW_BUILD_NUMBER`; `app.config.js` maps it to `ios.buildNumber` and `android.versionCode`. |
| `platforms.androidtv.submit.track` | Default Play track for `vibeview submit` (`internal`). |

Signing is wired up with two small Expo config plugins in `plugins/`,
because a managed project has no native project files to edit:

- `withVibeViewSigning.js` appends a guarded `signingConfigs.release`
  block to the generated `android/app/build.gradle`, reading the four
  `VIBEVIEW_*` Gradle properties VibeView provides during a production
  build. Without them the block is inert, so debug builds are untouched.
  One Android keystore covers Android TV.
- `withVibeViewIosSigning.js` sets manual code signing (team, provisioning
  profile) on the app target from `VIBEVIEW_DEVELOPMENT_TEAM` and
  `VIBEVIEW_PROVISIONING_PROFILE` at prebuild time. Doing it on the target
  — rather than on the `xcodebuild` command line, which would apply to
  every CocoaPods target too — is what the VibeView signing docs recommend
  for CocoaPods projects. tvOS uses the same distribution certificate as
  iOS with a tvOS-specific profile.

The credentials themselves were generated by VibeView
(`vibeview credentials generate --platform tvos|android --app <id>`) and
are scoped to this app; nothing secret is in the repository.

## Verifying it on a TV yourself

You need the `vibeview` CLI installed and logged in (`npm i -g vibeview`,
`vibeview login`). Every control has a `testID`; react-native-tvos maps it
to the tvOS accessibility identifier and the Android resource id, and
`vibeview find "<id>"` resolves it on both platforms. Ids: `home.title`,
`shelf.<shelf>`, `poster.<id>`, `home.mylist.count`, `detail.title`,
`detail.watch`, `detail.mylist`, `player.title`, `player.progress`.

```bash
# 1. Build both debug apps in the cloud (only needed after native changes).
vibeview build --cloud --platform all

# 2. Start Metro, then a detached session on the platform you want.
npm start &
vibeview dev --detach --json --platform tvos          # or androidtv
# → {"event":"session_ready","session_id":"…","url":"https://vibeview.io/sandbox/…"}

# 3. Drive it with the remote. Focused elements are marked in the tree.
S=<session_id>
vibeview ui-tree --session $S                # poster.harbor-lights is [focused]; "My list: 0 titles"
vibeview press dpad_right --session $S       # ~ "The Quiet Orchard" focused, ~ "Harbor Lights" unfocused
vibeview press dpad_down --session $S        # ~ "Salt and Tide" focused (first Documentaries poster)
vibeview find "poster.the-moon-garden-club" --session $S
vibeview tap-focused @<ref> --session $S     # Detail: detail.title = "The Moon Garden Club", Watch focused
vibeview find "detail.mylist" --session $S
vibeview focus @<ref> --session $S           # focus moves without selecting
vibeview press dpad_center --session $S      # button now reads "In my list"
vibeview press back --session $S             # Home; focus on that poster; "My list: 1 titles"
vibeview tap-focused @<poster ref> --session $S
vibeview press dpad_center --session $S      # Watch → Now playing: player.title, progress "7%" … "23%"
vibeview press back --session $S
vibeview press back --session $S             # Home again
vibeview screenshot --out check.png --session $S

# 4. Relaunch and check that My list survived.
vibeview press home --session $S
vibeview open-url "marquee://" --session $S
#   Apple TV asks "Open in “Marquee”?" with Open pre-focused → vibeview press dpad_center
#   Android TV: press home only pauses the app; to relaunch, `vibeview press back` on Home first
vibeview ui-tree --session $S                # "My list: 1 titles"

# 5. Always stop the session — it bills minutes while it runs.
vibeview dev-stop
```

The same commands ran unchanged on both platforms. The differences that
showed up: Apple TV reports the tree in points (1920×1080 or 3840×2160
depending on the device), Android TV in video pixels (1080×608); Android's
tree nests the poster's image and caption under the button and shows View
`testID`s as ids; Apple TV asks before opening a URL scheme, Android does
not; and on Android `press home` + `open-url` resumes the app rather than
relaunching it.

## Shipping

```bash
vibeview submit --check --platform tvos --bundle-id io.vibeview.marquee
vibeview submit --check --platform androidtv --package io.vibeview.marquee
vibeview credentials generate --platform tvos --name marquee --app <tvos app id>
vibeview credentials generate --platform android --name marquee --app <androidtv app id> --out <secrets dir>
vibeview build --cloud --production --platform all
vibeview submit --platform tvos --latest                        # → TestFlight
vibeview submit --platform androidtv --latest --track internal  # → Play internal track
```

Version 1.0.0 (build 1) of this app went to TestFlight and the Play
internal track this way.
